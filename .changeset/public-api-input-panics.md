Stop caller input from panicking or silently losing data. `decodeFrontiers` keeps the greatest id of a peer when the bytes repeat a peer, instead of producing frontiers that trap the next comparison. In detached editing, writing with a peer that already has ops after the current version throws `ConcurrentOpsWithSamePeerID` from the write instead of trapping, and the doc stays usable. `LoroText.update` and `updateByLine` throw the edit's error, such as a deleted container, instead of trapping. `import` now throws `UsedOpID` when the bytes bring no new ops but their content differs from the local ops with the same ids, and when they differ from updates still waiting for a dependency; repeating what the doc already has or has parked is still a no-op. A `JsonLossy` import of deeply nested values no longer overflows the stack. A local write throws `ConcurrentOpsWithSamePeerID` while updates of the same peer id, or updates that depend on that peer id, wait for a dependency, instead of breaking the import of that dependency; it works again once they apply, or with another peer id. An update that contradicts itself is rejected with `UsedOpID`.
